# 数据中心规划：选址、容量与能源基础设施

将数据中心看成“机房 + 场内设施 + 场外连接 + 区域容量与社区影响”。目标是产出能分工、取数、画图、比较和关闭问题的项目要求，不能仅总结知识。

## 先确定工作模式
- 新项目／看地：读 [site-survey.md](references/site-survey.md)，形成踏勘计划、约束图和选址判断。
- 规划／容量定义：读 [planning-basis.md](references/planning-basis.md)，形成参数台账、设施用地及分期接口要求。
- 方案检查／取舍：读 [review-and-tradeoffs.md](references/review-and-tradeoffs.md)，检查设施、失效工况、场外依赖和原则冲突。
- 追溯原文、核对概念：读 [source-digest.md](references/source-digest.md)。来源页码为 PDF 页码。
- 全流程：依次应用前三种模式；复制 [project-workbook.md](assets/project-workbook.md) 为项目版本，不改 skill 模板。

- 容量／面积／模块推演：读 [capacity-and-space.md](references/capacity-and-space.md)，显式定义五变量、单位和各类容量上限。
- 供能／冷却／低碳／经济比较：读 [energy-and-cooling.md](references/energy-and-cooling.md)，按工况、依赖和生命周期比较。
- 快速技术问答：只读有关模块，直接给结论、约束、计算或依据和待核项，不强制填整套工作簿。

## 版本与兼容
版本2.0.0，2026-10-22。GitHub入口为datacenter-site-planning；本地兼容入口dc-planning仅改变frontmatter name，模块内容一致。支持一般数据中心、Hyperscale、Colocation和AI/HPC的概念规划。保留原有踏勘和项目工作簿；新增容量与能源模块，撤销未经证实的通用阈值。使用可用工具完成研究、GIS/CAD或报表；没有真实工具与输入时只交付任务书／概念计算，不能声称完成解析、测量或工程验证。

## 最少输入与继续工作的规则
先读项目现有边界图、任务书、规划条件和公用事业函件。提取国家／辖区、地块边界与坐标系、项目类型与用途、IT负荷及分期、投运时间、可用性要求、冷却方案和已知电水限制。
缺项分为：阻止选址判断、阻止容量／布局冻结、可在概念阶段作区间假设。只集中问会改变当前决定的问题，其余登记“待确认”并继续。没有场地资料时输出取数与踏勘任务书，不能伪造现场观察。

## 执行方法
1. 建立项目边界：明确本地块、场外连接走廊、受影响公共系统和其他已承诺项目。按首期、远期及极端工况分别看。
2. 建立证据链：每项要求记录 ID、来源页／图／函件、证据日期、数值与单位、适用阶段、责任专业、验收证据和状态。标注 CONFIRMED（已证实）、WORKING ASSUMPTION（工作假设）、OPEN（待确认），同时区分“原文提炼／工程补充／当地规定”。
3. 先筛硬约束：合法用地、真实可接入电力及时间、热天可靠供水或经验证替代冷却、排放可接纳性、权属与通道、防洪及应急可达性。硬约束失败标红；资料不足标待证，不能算通过。
4. 用参数推设施，再用设施反查空间：每个设施明确功能、需求驱动、占地或包络、连接、检修／替换通道、外部影响、责任人。不得按原文示意图的设备数量套项目。
5. 比较至少两个可行方案（存在有意义的替代时），展示能源、水、土地、可靠性、交付、成本和社区影响的代价；硬约束不参与相互抵消。推荐一个，保留业主／专业负责人决定项。
6. 输出阶段结论：继续、附条件继续、暂停补证或不推荐。指出结论适用的阶段、负荷和假设，不能把概念可行写成接入批准或施工合规。

## 每次交付
按任务规模提供：一段建议与关键依据；约束图／需要补画的图层；参数与要求台账；设施与接口表；问题关闭清单。完整项目采用模板中的全部表格，单项任务只输出有关部分。
要求必须写成“对象 + 工况 + 可核查标准／待确认限值 + 提交证据 + 责任人 + 冻结前节点”。避免“考虑可持续性”等无法执行的表达。

## 决策边界
- 原文是2026年2月、以美国为主的入门白皮书，不是设计规范。当地法规、现行标准、业主任务书和公用事业书面条件须逐项核实，记录辖区、版本、日期与官方来源；未核实不填通用阈值。
- 接近变电站／水管／光纤不是已获容量、权利或独立路由；开发商预测不是接入承诺。
- IT MW、全站 MW、MVA、装机容量、平均与峰值必须分开；冗余容量不是日常能耗。
- 液冷、闭式循环、干式排热是不同层级；不能从其中一个标签推断全站零水耗。PUE不能单独代表总体可持续性。
- 不从 N+1／2N 直接推断 Tier 等级或认证；维护隔离、路径、共同失效及验证均需专业审查。
- 不将美国案例的退距、噪声限值、就业乘数、发电机时数或设备数量转成通用要求；不保证余热有买家或新能源凭证等于实时供电。
- 规划师负责土地、通道、邻避与公共利益；工程师负责容量、拓扑与工况证明；业主确认业务与风险偏好；主管机关／公用事业确认适用条件。skill 输出不代替签章。
