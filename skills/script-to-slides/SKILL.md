# Script to Slides

## Working agreement

Treat a presentation as two linked deliverables: what the presenter says and what the audience sees. Draft the narrative first, then translate it into slides and refine both together. The current user brief and supplied template take precedence over defaults. Preserve originals and create versioned outputs.

This workflow is the entry point for the user's combined script/slides requests. Use focused production skills below; do not also impose deck-builder's eight approval gates. Honour a user-requested staged review, otherwise continue authorised reversible drafting after resolving material gaps. Design choices belong to the user; an unconfirmed visual direction remains a draft, not Accepted.

## 1. Establish a compact brief

Reuse information already supplied. Usually confirm missing **purpose, audience and duration** together. Clarify whether duration includes Q&A, demonstration or other speakers. Record presentation language, script language, desired audience decision and deliverable stage. Do not assume this workflow-setup request is an actual deck commission.

Offer three tone presets when tone is unspecified:

| Preset | Appropriate use | Writing behaviour |
|---|---|---|
| Professional and natural — recommended | General business presentation | Clear connected speech, restrained claims, short sentences |
| Executive and concise | Management decision or progress report | Recommendation first, key evidence, decision and action |
| Explanatory and engaging | Technical explanation or knowledge sharing | Context, examples, clear transitions; define unfamiliar terms |

These are selectable defaults, not a claim about a permanently selected preference. If the user asks to proceed without answering, state provisional assumptions and draft accordingly. Keep unknown facts explicitly unresolved.

## 2. Build the evidence and script

Use supplied text, images, reports, PPT/PDF and Excel materials when available. Read the actual content, including slide/page locations or workbook sheet/ranges. Distinguish content evidence from visual inspiration and reusable layout references. An image is not evidence for an unverified numeric or project claim.

When materials are absent, use the purpose plus relevant project files and available confirmed memory. Explain historical dates and uncertainty; memory is a lead, not proof that an old fact remains current. Do not pull unrelated client facts into this project. If evidence remains thin, create a proposed storyline and clearly marked fact gaps; do not invent experience, numbers or citations. Research current facts when needed and permitted.

Write a spoken narrative with an opening, connected main points and a purposeful close. Use presentation-notes for natural delivery and handoffs, and write-like-me when matching the user's voice using available evidence. Separate on-slide wording from spoken explanation. Do not force the entire script onto slides.

## 3. Map script to slides

Maintain one versioned slide map as the source of truth for both outputs. For every slide record:

- Stable slide ID and current slide number; conclusion/title and audience takeaway.
- Concise on-slide content; visual/layout choice; supporting assets and source locations.
- Spoken notes; stage cues/transitions; allocated seconds and estimated speech duration.
- Component ID/version if reused; unresolved fact or asset gaps.

Preserve this relationship when slides are split, removed or reordered. Choose slide count from message complexity and timing, not a fixed slides-per-minute rule. Separate appendix/backup slides from planned speaking time.

## 4. Build branded slides

Use an available presentation-authoring tool or skill for deck reading, building, editing and rendering; read its template-following guidance when a template is supplied. Use an available speaker-notes workflow for notes, and PDF/spreadsheet tools only when those source formats require them. Named companion skills such as presentation-notes and write-like-me are optional and are not bundled; if unavailable, perform the equivalent work with available tools and disclose limitations. Load other production skills only for a concrete need.

Start from the supplied group/client PPTX or POTX: preserve its size, masters, colours, fonts, logos and page layouts. If there is no actual template, inspect relevant authorised project assets or establish an explicitly labelled draft visual style with the user. Do not claim that a reconstructed template is an approved master. Default to 16:9 only when no source or user choice establishes size; record it as an assumption. Do not distort images or blindly scale components from a different aspect ratio.

Use source PPT slides as editable components where feasible; PDF/image references may guide design but are not automatically editable. Use Excel values with units, period and source range, checking formulas and totals relevant to the claim. Prefer editable charts/tables when useful. Retain image provenance and use restrictions.

For a new unconfirmed visual direction, offer a representative cover/content sample for a meaningful design choice. Do not require sample approval again for an already selected template unless there is a material change. Missing logos or licensed assets remain explicit gaps; never invent official branding.

## 5. Synchronise notes and timing

Embed the final per-slide script in each slide's PowerPoint speaker-notes area when PPTX is requested. Keep stage cues visibly distinct from spoken text. Provide a separate readable notes file as well. If the tool cannot embed notes, disclose the limitation rather than claiming a complete integrated deck.

Calculate available speech time after Q&A, demonstrations, handoffs and pauses; allocate it by message importance. English estimates may start at 100–130 spoken words/minute, adjusted for technical content and the presenter. For Chinese or mixed language, use an explicit suitable estimate or rehearsal sample instead of English word counting. Show timing as an estimate, with per-slide and total time. If over budget, shorten or move material to an appendix; do not simply relabel the duration.

## 6. Review, deliver and reuse

Render and inspect all slides using the presentation workflow. Check clipping, overlaps, readability, image cropping, source/number fidelity and brand consistency. Reopen the output to verify slide order, notes presence and slide-to-script mapping. Check the total time against the brief; record checks actually performed and any unavailable checks.

Deliver a versioned editable deck, per-slide notes, slide map with timings and source references, and a concise list of unresolved items. Do not mark Accepted without human acceptance or send externally without authorisation.

For future work, read [component-library.md](references/component-library.md) when extracting, selecting or updating reusable content. Maintain general methods in this skill; store component assets and project facts outside the skill. Reuse explicit user corrections for the current assignment; persistent preference changes require the user's request.
